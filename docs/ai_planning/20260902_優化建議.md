# 收盤價資料整合後之分析優化作業文件

## 背景

專案已取得完整每日收盤價資料（`api_close1_*.parquet`），欄位包含：
`symbol, name, trade_date, market, open, high, low, close, change, volume, transaction_count, turnover, last_bid_price, last_ask_price`

目前 `close_price_files` 已局部串接進 [cloud_report_generator.py](../../cloud_report_generator.py) 與 [chip_intelligence_analysis.py](../../chip_intelligence_analysis.py)，但僅用於：
- 點火日→最新收盤價之回測報酬率 (`return_pct`, `backtest_win_rate`, `backtest_avg_return_pct`)
- 分點成交集中度 (`concentration_pct`)
- 分點加權平均操作價位 (`build_broker_profile`)

尚有大量欄位（`high`/`low`/`change`/`volume` 等）與可能性尚未被利用，本文件規劃後續優化項目。

---

## 🥇 P0：低成本、高價值（資料已就緒，僅差運算邏輯）

### 1. 成本偏離度 (Cost Deviation)
- **現狀**：規劃文件 [cloud_daily_report_planning.md](cloud_daily_report_planning.md#L44) 已列出此欄位，但程式碼尚未實作。
- **做法**：[cloud_report_generator.py](../../cloud_report_generator.py) 中已有 `buy_avg_price`（主力買進均價）與 `latest_close`（最新收盤價），新增：
  ```
  成本偏離度% = (latest_close - buy_avg_price) / buy_avg_price * 100
  ```
- **價值**：直接標示「主力已套牢 / 已獲利 N%」，比現有 `return_pct`（點火日→現價）更貼近主力真實損益，且無需額外資料查詢。
- **影響範圍**：`cloud_report_generator.py`（HTML 表格新增一欄）、`find_similar_cases.py`（可選同步）。

### 2. 持有期間最大獲利/最大回撤 (MFE / MAE)
- **現狀**：回測僅計算「點火日 vs 最新收盤」單點報酬，未使用 `high`/`low`。
- **做法**：在點火日至今的區間內，額外查詢 `MAX(high)`、`MIN(low)`，計算：
  ```
  期間最大漲幅% = (MAX(high) - ignition_close) / ignition_close * 100
  期間最大回撤% = (MIN(low) - ignition_close) / ignition_close * 100
  ```
- **價值**：讓 `backtest_win_rate` / `backtest_avg_return_pct` 更真實反映訊號品質（例如訊號曾經大漲後又回吐，單看最新收盤會低估訊號價值）。
- **影響範圍**：`cloud_report_generator.py` 的回測區塊。

### 3. 異常波動過濾（除權息 / 漲跌停）
- **現狀**：`change` 欄位尚未被用來過濾資料。
- **做法**：偵測除權息缺口（開盤價相對前收異常跳空）或漲跌停鎖死日（`change` 達到當日漲跌幅上下限），於計算「買均價 vs 現價」「勝率回測」時排除或另行標註。
- **價值**：避免除權息缺口或極端行情污染成本偏離度與回測報酬率的準確性。
- **影響範圍**：`cloud_report_generator.py`、`find_exit_cases.py`。

## 🥈 P1：中等投入，強化訊號品質

### 4. 量價背離偵測
- **做法**：結合分點淨買超與當日漲跌幅，新增偵測函式（可比照 `chip_intelligence_analysis.py` 現有的 `detect_reversal_warning`）：
  - 股價平盤/下跌但主力仍大力買超 → 標記「逆勢吸籌」
  - 股價上漲但主力淨賣超 → 標記「拉高出貨」
- **價值**：大幅提升 `find_similar_cases.py` / `find_exit_cases.py` 標籤的可信度，減少假訊號。
- **影響範圍**：`chip_intelligence_analysis.py` 新增偵測函式。

### 5. 點火日相對高低位置
- **做法**：利用收盤價檔案判斷點火當日股價是否接近近 N 日低點（低接布局）或近 N 日高點（追價型）。
- **價值**：對應規劃文件中提及但尚未實作的「低檔佈局」標籤，可作為風險分級依據。
- **影響範圍**：`cloud_report_generator.py` / `find_similar_cases.py` 標籤邏輯。

### 6. 分點歷史勝率排行榜
- **做法**：`build_broker_profile()`（[chip_intelligence_analysis.py](../../chip_intelligence_analysis.py#L179)）目前僅統計操作標的數與均價，可串接收盤價回測，計算「該分點過去點火後平均報酬率/勝率」。
- **價值**：建立分點信譽評分，未來新訊號出現時可依分點歷史戰績加權排序，優先關注高勝率分點。
- **影響範圍**：`chip_intelligence_analysis.py` 的 `build_broker_profile()`。

---

## 🥉 P2：較大工程，長線價值

### 7. 訊號有效性統計驗證
- **做法**：將歷史所有「重押/出貨」訊號與後續 5/10/20 日報酬率做全樣本統計（勝率、平均報酬、IC 相關係數）。
- **價值**：驗證現行門檻參數（`--min-amount`、`--min-ratio` 等）是否真的有效，作為未來調參依據。

### 8. 對大盤/類股相對強度
- **做法**：若收盤價檔案涵蓋大盤指數或類股資料，計算「個股報酬 - 大盤（或類股）報酬」之超額報酬。
- **價值**：排除大盤齊漲齊跌造成的雜訊，讓主力訊號的超額報酬更精準。
- **限制**：需確認收盤價資料是否包含大盤指數／類股分類資料，若無則需額外建置對照表。

---

## 執行建議順序

1. P0 三項可一次性實作，改動集中在 `cloud_report_generator.py`，風險低、立即可用。
2. P1 視實際訊號誤判率決定優先順序，建議先做「量價背離偵測」（第4項）。
3. P2 屬於長線驗證工程，建議累積足夠歷史訊號樣本後再進行。
